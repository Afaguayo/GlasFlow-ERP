# Deployment

## Cloud demo (Render, free tier)

The repository ships a `Dockerfile` and a `render.yaml` blueprint. The container runs the API and the web UI on **SQLite** (no database server). The demo data is seeded on every fresh start, so each restart begins from the same clean data set. The full SQL Server setup is the local/on-premises configuration described in the README.

1. Sign in at https://render.com with GitHub.
2. **New → Blueprint**, select the `GlasFlow-ERP` repository, confirm the `glasflow-erp` service.
3. Enter the two secret values when prompted:
   - `Auth__DemoPassword`: password for the demo users `admin`, `operador`, `consulta`.
   - `Ai__ApiKey`: a Google AI Studio (Gemini) API key. Leave it empty to use the deterministic assistant.

   `Auth__JwtKey` is generated by Render automatically.
4. Deploy. The first build takes a few minutes; the app is then at `https://glasflow-erp.onrender.com` (or the name Render assigns).

Notes
- **Cold starts.** The free tier sleeps after about 15 minutes without traffic, and the first request afterwards takes 30–60 s. Open the URL a couple of minutes before a demo.
- **Data resets.** Data is reset when the service restarts or redeploys; changes made during a demo are temporary.
- **Gemini protection.** The key is used through the OpenAI-compatible endpoint (`Ai__BaseUrl`, model `gemini-3.5-flash`). It is protected by login and by the assistant rate limit (20 requests/min).
- **Same image elsewhere.** The image also runs on Fly.io, Azure Container Apps or any Docker host: map port 10000 and set the same environment variables.

## Local / on-premises (SQL Server)

See the README "Installation" section: SQL Server 2022 Express, the API applies migrations and installs the procedures, views and triggers on startup. Use `dotnet user-secrets` (already enabled for `GlasFlow.Api`) or environment variables for `Auth:JwtKey`, `Auth:DemoPassword` and `Ai:*`.

## Verification status

- **Production mode verified locally.** The release build was run with `ASPNETCORE_ENVIRONMENT=Production` on SQLite: health check, web UI, Swagger, login, dashboard and system status all worked.
- **Linux build verified.** `dotnet publish -r linux-x64` succeeds and includes the native SQLite library and the web UI.
- **Container image not built locally.** Docker is not installed on the development machine, so the image itself was not built or run here. Render builds it from the `Dockerfile`.
